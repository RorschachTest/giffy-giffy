How a clip becomes searchable

A clip dropped into data/inbox goes through ten steps. Each step adds facts to the clip's record, and search later reads those facts in three ways: by words, by meaning, and by topic. The examples below are real values from the running stack: clip 6, ravi kishan money follows, and the query salary day.

How search finds it

Each search reads the query three ways, by its spelling, its meaning and what it is about, then ranks everything in one database query. A share teaches the clip a new way to be found.

The score for "salary day" → clip 6

No word of the query appears in the clip, so the word and meaning scores are low. The topic match carries it to the top. The topic boost shrinks as the word match grows, so a query that names a clip by its title or quote is never overtaken by another clip with the same topic.

kw · words0.21

Fuzzy match of the query against names, dialogue, people and the rest.

sem · meaning0.15

Cosine similarity between the query and the clip's embedding.

tm · topic0.99

Laya read the query as money; the clip has #money.

score0.385

Shown when kw ≥ 0.35, sem ≥ 0.45 or tm ≥ 0.5. Here tm qualifies it.

score = 0.65 × kw + 0.35 × sem + 0.25 × tm × (1 − kw) + popularity = 0.65 × 0.21 + 0.35 × 0.15 + 0.25 × 0.99 × (1 − 0.21) = 0.138 + 0.052 + 0.196 = 0.385

When a model is missing

  • Laya down or LAYA_URL empty: the clip gets laya_failed, mood falls back to the plain embedder, and search runs on words and meaning only.
  • Faces off: no people from faces, mood uses scene and text.
  • Any error inside one clip: the original moves to data/failed with a traceback in .error.txt.

Redoing old clips

  • python -m app.reindex rebuilds the search columns after a rule change.
  • --laya adds Laya topics; --vibe fills empty mood fields.
  • --vibe --replace recomputes mood on every clip, including hand-edited ones.
